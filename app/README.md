# TRUSTCAM mobile

```sh
npm ci
npm run typecheck
npm run self-check
npm run config-check
npx expo-doctor
npx expo start
```

VI mặc định; English/Tiếng Việt và giao diện sáng/tối lưu bằng SecureStore. Năm tab cố định dùng React state; Cài đặt ở header. Checklist/Báo cáo/Kiểm tra luôn mở danh sách hồ sơ trước, chọn hồ sơ rồi xem chi tiết; nút về danh sách giữ phiên đang làm việc của Home/Camera.

- API: cấu hình `EXPO_PUBLIC_API_URL` lúc build. Chỉ development (`__DEV__`) mặc định `http://localhost:8000` và cho sửa URL trong Cài đặt để thử LAN. Đổi URL cần xác nhận, giữ chỉ mục hồ sơ theo máy chủ, chỉ đổi bộ nhớ sau khi SecureStore lưu thành công; không chuyển token cũ sang host mới. Production ẩn URL/IP ở Home, hồ sơ, xác nhận doanh nghiệp và metadata ảnh trong Cài đặt; vẫn giữ trạng thái kết nối, tải lại và đồng ý chia sẻ rõ ràng bằng VI/EN. Thiếu/sai cấu hình build hoặc URL đã lưu khác URL build: cảnh báo và chặn mọi yêu cầu mạng, không tự đổi URL/token. Cần bản build đúng dịch vụ cho hồ sơ đã lưu; chưa có migration/chuyển dịch vụ trong production. Không chứa API key.
- Native build: `npx expo run:android` sau khi cài Android SDK, Java và kết nối thiết bị. Chưa build/chạy thiết bị trong môi trường này: không có `adb`, `sdkmanager`, `ANDROID_HOME` hay SDK tại đường dẫn mặc định.
- Expo SDK 58.0.25 / RN 0.88.1 / React 19.3.0 xác minh bằng npm registry và template thật, trùng số phiên bản trong kế hoạch.
- Kế hoạch dùng API noble v3 sai. `@noble/ed25519` v3.2.0 README nêu bản viết lại chưa audit độc lập; chọn nhánh v1.7.5 có lịch sử audit cure53 v1 (không tuyên bố mọi patch đều audit). API thật: `ed.utils.sha512Sync`, `ed.sync.getPublicKey`, `ed.sync.sign`, SHA-512 từ `@noble/hashes/sha2.js` v2.4.0. Seed tạo bằng `expo-crypto`, lưu một lần SecureStore; không dùng subtle Ed25519.
- Ký byte UTF-8 canonical manifest trực tiếp, không bọc SHA-256 manifest. Băm đúng byte ảnh, lưu bản riêng, tải chính bản đó. Không nén sau ký. Giới hạn 10 MiB.
- Chia sẻ tệp gốc tại tab Phiên để đối chiếu ở tab Kiểm tra. Thư viện ảnh có thể chuyển mã; ảnh trông giống nhau vẫn FAIL khi byte khác. Bản gốc nằm trong vùng tài liệu riêng của ứng dụng; metadata cục bộ lưu bền theo máy chủ + phiên + bằng chứng; nút chia sẻ khôi phục sau mở lại ứng dụng.
- JSON báo cáo hiển thị và chia sẻ nguyên dữ liệu kỹ thuật máy chủ; nhãn/giải thích UI VI/EN. Luôn CHECKLIST; VLM tùy chọn chỉ xuất hiện khi `/health` xác nhận cấu hình, không có corpus pháp lý, không bịa độ tin cậy hoặc trích dẫn. PASS không chứng minh cảnh/thời gian/giá trị pháp lý.
- Plugin `withLanHttp.cjs` cho phép HTTP Android để demo LAN tin cậy; triển khai thật dùng HTTPS và bỏ ngoại lệ này. iOS cho phép mạng cục bộ. Lý do quyền camera/ảnh viết song ngữ; hộp thoại hệ điều hành theo ngôn ngữ hệ điều hành. Không xin microphone/Face ID.
- Kiểm tra: `self-check` gồm RFC 8032 vector 1, OpenSSL xác minh độc lập, fixture canonical giống Python, parity VI/EN, URL/10 MiB, HTTP thật local cho auth/lỗi/timeout/redirect. `config-check` introspect quyền native, bắt hồi quy plugin image-picker vô tình xoá quyền camera.
- `npx expo export --platform all --output-dir dist` đã xuất bundle Hermes Android và iOS. Không thay thế kiểm thử camera/SecureStore/chia sẻ trên thiết bị thật.
- Mở app tự tải phiên từ token đã lưu; lỗi mạng giữ nguyên token và có nút Tải lại. Trạng thái `finalized` khóa chụp/tải và chốt lại. `GET /session/{id}/report` dùng bearer để mở báo cáo cũ, không cần chốt lại. Backend cũ thiếu các trường bổ sung vẫn đọc được checklist; cần backend mới để khôi phục báo cáo sau mở app.
- Phân tích ảnh: `POST /evidence/{evidence_id}/analyze` với bearer và `{}`. Mỗi lần gửi đều có Alert VI/EN công khai rằng ảnh chuyển tới nhà cung cấp mô hình ngoài; không phân tích tự động, không hiển thị URL/key nhà cung cấp. Nút khóa khi đang xử lý hoặc phiên đã chốt. Nhận xét `accepted`/`retake`/`uncertain` chỉ tham khảo, giữ nguyên lý do mô hình, không giả dịch VI/EN. Nút Chụp lại trên ảnh hiện tại mở camera với mục tiêu UUID rõ ràng; hủy được, kể cả khi checklist đã đủ. Giới hạn 5 phiên bản mỗi chuỗi ảnh; ảnh cũ giữ trong lịch sử, không phân tích lại ảnh đã lưu lịch sử. Checklist không bị nhận xét mô hình chặn chốt.
- `self-check` thêm validator phiên/báo cáo/VLM, tương thích trường thiếu ở backend cũ, chặn thao tác sau chốt, xác nhận trước yêu cầu và thứ tự lưu trước khi bỏ tham chiếu. Kiểm tra source wiring không thay thế kiểm thử Alert/SecureStore trên điện thoại.
- Lần kiểm tra bổ sung: `npx expo lint` tự đề nghị cài ESLint vì dự án chưa có cấu hình; cài đặt timeout 120 giây. Đã bỏ hai dependency tự thêm khỏi package.json; lockfile không đổi, ESLint không cài thành công. Chưa có kết quả lint.
- `npm audit`: 3 cảnh báo moderate trong chuỗi Expo fingerprint/minimatch; không chạy `audit fix --force` vì đề xuất hạ SDK không tương thích.

## Bổ sung chức năng sau rà soát

- Giữ Expo Go SDK58, không thêm dependency/UI library. Không dùng mock UI/UX làm dữ liệu, chữ ký, kiểm tra hoặc trạng thái thật.
- Camera dùng getter thứ ba `useCameraPermissions()` để đọc lại quyền khi quay về foreground; lỗi Promise hiển thị VI/EN. Chỉ reset preview khi trạng thái active đổi, tránh sự kiện active lặp làm mất trạng thái sẵn sàng. Camera chọn kích thước thực qua `getAvailablePictureSizesAsync()` / `pictureSize`: ưu tiên gần 1920×1080 và <=4 MP nếu có; nếu không, chọn kích thước nhỏ nhất <=20 MP. Không có kích thước hợp lệ thì khóa chụp. `quality: 0.85` áp dụng lúc chụp, trước ký. Kiểm tra kích thước ảnh thực <=20 MP và byte <=10 MiB trước ký/tải. Không đổi byte sau ký.
- Transport: chỉ catch riêng Promise `fetch`, mọi rejection chuyển `network_error`; không kiểm tra `error.name`, không đưa thông báo native riêng tư ra UI. Lỗi HTTP backend dùng allowlist, timeout vẫn `timeout`. Test đọc và transpile đúng lớp `FetchError extends Error` từ SDK58 đã cài, không giả làm TypeError.
- Retake: xác nhận rõ ảnh gốc/chữ ký cũ vẫn giữ. Tạo byte mới, canonical manifest 6 trường mới, chữ ký mới; `replaces_evidence_id` là trường multipart riêng, không nằm trong manifest. Upload thường không có trường này; duplicate vẫn do server từ chối. Thành công tải lại current + history, xóa mục tiêu cũ. `stale_evidence` thử tải lại rồi yêu cầu chọn/xác nhận lại; không tự đổi mục tiêu. `revision_limit_reached`, `invalid_replacement`, `evidence_superseded` có VI/EN. Phiên finalized không chụp lại. Kiểm tra chọn được cả ID hiện tại và lịch sử; chỉ ảnh hiện tại có phân tích, luôn cần đồng ý chuyển dữ liệu ra nhà cung cấp.
- Validator phiên/báo cáo đọc `evidence_history` cùng cấu trúc Evidence, optional predecessor UUID hoặc null; ID duy nhất xuyên hai mảng, slot lịch sử có thể lặp. Backend cũ thiếu history đọc thành mảng rỗng. Giữ quy tắc khôi phục phiên/báo cáo đã chốt.
- Bản sao riêng trong `Paths.document/trustcam-photos-v1/`, tên `trustcam-<UUID>.jpg`. Mỗi ảnh có JSON metadata nhỏ, không token/seed; scope base+session+evidence, trạng thái chờ là evidence_id null. Ghi pending trước request upload; timeout/lỗi không xóa ảnh. Refresh đối chiếu hash+slot+captured_at với current và history để liên kết upload kết quả chưa rõ, không tự tải lại ảnh chờ. Ghi hai journal bất biến `.json` và `.linked.json` qua temp + rename tới tên chưa tồn tại. Không dùng overwrite iOS (mã native SDK58 xóa đích trước move nên không bảo đảm thay thế atomic). Nếu crash trước metadata, ảnh vẫn hiện như orphan để chia sẻ/xóa có xác nhận.
- Cài đặt hiển thị mọi bản sao, cả phiên/máy chủ cũ, pending và orphan. `Xóa bản sao cục bộ` có xác nhận không thể hoàn tác, giải thích dữ liệu máy chủ không đổi; chỉ xóa tên thuộc ứng dụng qua root cố định. Duyệt cả tên cũ `Paths.document/trustcam-<UUID>.jpg`, không quét/xóa tệp tùy ý. Không tự xóa theo tuổi hoặc khi đổi phiên/URL. Xóa một phần giữ tệp còn lại; metadata chỉ xóa sau ảnh, tệp metadata còn sót được liệt kê để thử lại. Sidecar lỗi báo `storage_error`, không bỏ ảnh. Ảnh pending chia sẻ được, nhưng chưa có nút gửi lại ảnh pending: tải lại phiên để đối chiếu, hoặc chia sẻ giữ bản gốc trước khi chụp mới.

## Hồ sơ cục bộ và ảnh bổ sung

- Một phiên là một hồ sơ. Chỉ mục `trustcam.preferences.v1` giữ `{base, credentials, dossiers}` trong **một giá trị SecureStore**. Mỗi mục giữ base chuẩn hóa, session ID, bearer, device ID và thời gian tạo cục bộ nếu biết. Token không đi vào metadata ảnh, AsyncStorage, UI hoặc log. Dữ liệu cũ `{base, credentials}` chuyển thành một hồ sơ; thời gian cũ ghi không rõ, không bịa thời gian/owner. Không thể khôi phục phiên trước đây đã mất bearer.
- Giới hạn **4 hồ sơ tổng cộng trên mọi máy chủ**, đồng thời **2000 byte UTF-8** cho toàn giá trị. Expo SDK58 ghi nhận một số iOS từng từ chối giá trị khoảng trên 2048 byte; test đo bốn mục UUID + bearer 43 ký tự dưới 2000 byte. URL/token dài có thể đạt trần sớm hơn. Không tự loại mục cũ. Nâng trần cần migration chia nhỏ có transaction; hiện chưa có xóa chỉ mục. Lỗi native vẫn xử lý ngay cả dưới trần.
- Tạo/chọn hồ sơ và đổi API chỉ đổi credential/state sau khi ghi SecureStore thành công. Test chạy callback App thật với native IO doubles cho lỗi ghi cả ba đường. Hồ sơ cũ luôn được giữ; nếu server tạo phiên thành công nhưng native ghi thất bại, phiên mới có thể thành bản ghi máy chủ không truy cập lại được sau khi đóng app. Không tuyên bố transaction xuyên server + SecureStore.
- Danh sách chỉ lọc host hiện tại; không gọi dashboard/global listing hoặc tự fetch mỗi card. Tóm tắt chỉ cache trong RAM sau tải thật, đánh dấu cache; sau restart hiện chưa tải, không giả số ảnh. Mở hồ sơ tải session và báo cáo đã chốt bằng bearer đúng host; lỗi giữ mục đang chọn cùng nút tải lại. Đổi URL không gửi bearer cũ tới URL mới.
- Khi server trả `max_evidence: 20`, Camera hiện **Thêm ảnh** với bốn nút nhóm sẵn có, chỉ sau đủ bốn nhóm và dưới 20 ảnh hiện tại. Chỉ thao tác này gửi multipart `additional=true`; canonical manifest vẫn đúng sáu trường và bốn enum slot. Server cũ thiếu capability không nhận upload bổ sung. Chụp lại luôn dùng UUID chính xác, không gửi flag additional; metadata bổ sung do server giữ theo mục tiêu.
- Validator nhận tối đa 20 current + 80 history; `is_additional` optional boolean, duplicate primary cùng slot bị từ chối, supplementary cùng slot được phép. Chốt cần đủ bốn nhóm, không cần đủ 20 ảnh. Tiến độ tách số ảnh hiện tại `/20` và số nhóm bắt buộc `/4`; checklist hiển thị bốn nhóm. Retake đếm predecessor theo từng chuỗi, không đếm chung history cùng slot.
- `localPhotos.ts` không có snapshot/mảng giới hạn bốn ảnh: sidecar riêng từng ảnh; không cần nâng trần/chuyển metadata. Scope khớp base+session+evidence và giữ file gốc không đổi.
- Kiểm tra lần này: `npm run typecheck`, `npm run self-check`, `npm run config-check` PASS; export Hermes Android/iOS tại `/home/rcong/.hermes/cache/scratch/trustcam-dossier-export`. Chưa kiểm thử camera/SecureStore/Alert trên điện thoại; chưa gọi upload bổ sung vào backend chạy thật hoặc provider. Lệnh lint CI bất ngờ tự gọi cài ESLint rồi timeout 60 giây; đã bỏ hai mục tự thêm khỏi package.json và tái tạo lockfile offline không còn ESLint. Không còn khai báo/lock ESLint; kiểm tra xác nhận `node_modules/eslint` và `node_modules/eslint-config-expo` còn tồn tại do lần cài ngoài ý muốn. Chưa hoàn nguyên node_modules vì không có snapshot trước đó. Chưa có kết quả lint.
